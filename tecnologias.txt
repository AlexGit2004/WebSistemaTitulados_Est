TECNOLOGÍAS DEL PROYECTO (sistema1_5)
=====================================

FRONTEND (cliente / interfaz de usuario)
----------------------------------------
- Next.js 14.2.5: framework full-stack de React. Usa App Router para el sistema de rutas y páginas. Orquesta front y back en un solo proyecto.
- React 18: librería base para construir los componentes de la interfaz (estado, props, hooks).
- TypeScript 5: lenguaje tipado sobre JS. Da seguridad en tipos, autocompletado y menos errores en runtime.
- Tailwind CSS 3.4: framework de estilos en utilidades (clases CSS). Se usa para todo el diseño/responsive (navbar, tarjetas KPI, heroes).
- lucide-react: paquete de iconos SVG (users, charts, graduación, etc.).
- recharts: librería de gráficos. Se usa para los KPI: barras por año, pie por sector laboral, etc.
- react-hook-form + @hookform/resolvers: manejo de formularios (campos, validación en cliente).
- zod en frontend: esquemas de validación de datos de formularios.
- xlsx: exportación de datos a Excel (reportes).
- date-fns: utilidades de fechas.
- clsx + tailwind-merge: utilidades para combinar clases CSS condicionalmente.

BACKEND (servidor / lógica de datos)
------------------------------------
- Next.js API Routes (App Router): endpoints REST en src/app/api/* (auth, dashboard, exportar, personas). No usa Express: los handlers son funciones GET/POST.
- PostgreSQL: base de datos relacional (local, puerto 5432, BBDD sistitulados_db).
- pg: driver de Node para conectar a PostgreSQL.
- Drizzle ORM 0.33: ORM moderno tipo TypeScript. Define el esquema (src/db/schema.ts), consultas tipadas y migraciones.
- drizzle-kit: herramienta de CLI para push/generate/migrate/studio de la base de datos.
- zod en backend: validación de datos recibidos en las API.
- dotenv: carga de variables de entorno (.env.local).

SEGURIDAD / AUTENTICACIÓN
-------------------------
- Autenticación por CI/correo contra PostgreSQL (tablas usuarios y personas) + fallback de admin demo (admin@umsa.bo) hardcodeado en la API de login.
- Sesión en el cliente: el usuario autenticado se guarda en localStorage (clave auth_user) vía contexto React (src/lib/auth.tsx).
- No usa JWT ni bcrypt: las contraseñas se comparan en texto plano en el login. Es un sistema en etapa de prototipo; para producción se recomienda hash de contraseñas (bcrypt/argon2) y sesiones seguras con httpOnly cookie.
- validación de roles: admin / TITULADO / EGRESADO controla qué se muestra en la UI.

HERRAMIENTAS / INFRA
--------------------
- pnpm: gestor de paquetes (lockfile pnpm-lock.yaml).
- tsx: ejecuta scripts TS (scripts/seed.ts para datos de prueba).
- TypeScript + ESLint (next lint) para calidad de código.
- Next.js standalone: build de producción (next build / next start).
